# Contributing Guide

Thank you for your interest in contributing to this demo project!

## Getting Started

Before contributing, please read our [main documentation](DOCUMENTATION.md) and check the [changelog](CHANGELOG.md) for recent updates.

## Development Setup

1. Read the [architecture overview](docs/developer-guide/architecture.md)
2. Follow the [getting started guide](docs/user-guide/getting-started.md)
3. Review our [testing procedures](docs/developer-guide/testing.md)

## Contribution Guidelines

### Documentation
- All documentation should include proper cross-references
- Use relative links when referencing files within the project
- Add anchor links for easy navigation within documents
- Update the [README](README.md) when adding new files

### Code Examples
- Add examples to the [examples directory](examples/)
- Start with [basic examples](examples/basic/) before creating [advanced ones](examples/advanced/)
- Reference examples from relevant documentation

### API Changes
- Document API changes in the [API changelog](api/changelog/api-changelog.md)
- Update [API reference](api/reference/api-overview.md) documentation
- Include [endpoint documentation](api/reference/endpoints.md) for new APIs

## Link Navigation Testing

When contributing, please test:
- **Relative links**: Ensure `[text](file.md)` works correctly
- **Folder navigation**: Test `[text](folder/file.md)` links
- **Anchor links**: Verify `[text](#section)` and `[text](file.md#section)` work
- **Cross-references**: Check links between different documentation sections

## Review Process

1. Ensure all links work correctly
2. Test with both relative and absolute paths
3. Verify anchor links function properly
4. Check that new files are referenced in [README](README.md)
